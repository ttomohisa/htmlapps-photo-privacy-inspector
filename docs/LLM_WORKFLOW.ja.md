# LLMでアプリを作る手順

## 推奨プロンプト

リポジトリをLLMへ渡し、次のように指示します。

> 最初に `AGENTS.md` を全文読み、その後 `APP_SPEC.md` と `docs/ARCHITECTURE.md` を読んでください。確認ダイアログなど共通UIを作り直す前に `components/` も確認してください。仕様に記載されたアプリを最後まで実装してください。単一HTML、ローカル処理、実行時通信なしという制約を維持し、必要に応じてソース、設定、ライセンス表記、日英README、変更履歴、検証処理を更新してください。完了報告前にビルドと検証を実行してください。`dist/index.html` と `dist/index.self-extract.html` は直接編集しないでください。

## 基本の進め方

1. `APP_SPEC.md` を新しいアプリの具体的な仕様へ書き換えます。
2. `components/` を確認し、使える汎用UI部品があれば再利用します。
3. `app.config.json` の名前、slug、バージョン、説明を変更します。
4. LLMにはサンプルをすぐ削除させず、まず現在の構成を確認させます。
5. 外部ライブラリが本当に必要な場合だけ、固定バージョンで `dependencies.json` へ追加させます。
6. 実装のまとまりごとにビルドさせます。
7. `dist/dependency-manifest.json` を確認し、想定外の依存や素材がないか確認します。
8. 生成された2種類のHTMLを直接開き、主要操作を確認します。
9. 実行時通信がないことを確認してから公開します。

## LLMへ渡すと精度が上がる情報

- 入力例と上限サイズ
- 出力形式とファイル名規則
- 破壊的操作とUndoの範囲
- スマートフォンのジェスチャーとスクロール挙動
- 空、処理中、成功、エラーの各状態
- 保存先、復元、初期化のルール
- アクセシビリティ要件
- 対象ブラウザーと端末
- 見た目が重要な場合の参考画像

## LLMにさせないこと

- 実行時サーバーが必要なフレームワークへの置換
- 一時的なCDN参照の追加
- 分析タグ、外部フォント、トラッキング、無断の更新確認
- Worker、WASM、フォント、辞書だけを外部に残した状態での「完全オフライン」表記
- 外部ライブラリの圧縮済みコードをソースへ直接貼り付けること
- 動かないボタンで未実装を隠すこと
- `dist/index.html` または `dist/index.self-extract.html` の直接編集

## 確認しやすい区切り

- 状態モデルの実装完了
- PCで主要操作が完了
- タッチ操作と狭い画面への対応完了
- 入出力処理の完了
- 依存関係とライセンスの確定
- ビルドと通信遮断検証の完了
